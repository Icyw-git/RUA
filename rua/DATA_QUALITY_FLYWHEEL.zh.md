# RUA 数据质量标签与自动回流设计

## 目标与当前起点

目标是从完整运行记录中找出适合 WLA 模仿的动作窗口，同时保留错误和失败经历，供恢复训练及后续价值学习使用。质量判断必须能追溯到动作前后状态、视频或仿真事件；速度和路径长度只能描述行为，不能单独判错。

现有 `quality_screen.py` 会确认成功与数据完整性，比较同任务步数，并指出夹爪闭合→张开→闭合的位置。`oracle_feedback.py` 能精确回放动作，保存逐步目标条件和目标物体位置。两者尚不能证明一次夹爪闭合抓住了物体，也不能断定绕行是否错误。当前 Pro 扩展测试的 26 条轨迹可用于校验标签生成流程；其中 14 条通过基础技术检查，不代表已经逐段确认质量。

## 标签：事实、行为、效率分开

每条原始 episode 保留 `official_success`、`status`、任务、来源和动作数。逐步或连续区间的自动标签另存，不改原始 trace。任务动作编号使用 `[start,end)`；初始化动作不计入。

| 轴 | 字段 | 值 | 判定依据 |
| --- | --- | --- | --- |
| 任务阶段（辅助） | `task_phase` | `approach`、`transport`、`place`、`articulate`、`unknown`、`null` | 只描述能识别的任务阶段；边界不清时为空，不参与训练筛选 |
| 可观察事件 | `events` | `target_grasped`、`grasp_missed`、`gripper_cycle_unresolved`、`wrong_object_grasped`、`target_dropped`、`target_release_unresolved`、`goal_gained`、`goal_lost`、`wrong_drawer_moved` | 回放后的物理状态和目标条件；每个事件单独保存动作编号和证据，空列表表示没有确认事件 |
| 行为角色 | `role` | `nominal`、`recovery`、`error`、`uncertain` | 事件发生前后的局部任务状态；`recovery` 必须有先前偏差及后续有效纠正 |
| 证据等级 | `verification` | `verified`、`candidate`、`unknown` | `verified` 要有可重放的物理或目标条件证据；动作形状、速度、夹爪命令只产生 `candidate` |
| 可观测范围 | `coverage` | `complete`、`partial` | 只表示本任务所需的物体、接触或关节状态是否逐步可用；不能用“没检测到错误”代替 `complete` |
| 效率描述 | `speed_ratio`、`path_ratio`、`stationary_steps` | 数值或 `null` | 与同任务、同扰动、相近初始难度的成功轨迹相比；参考不足时为空 |

`events` 描述发生了什么，`role` 描述这一段对当前任务的作用。例如双物体任务中“放下第一件物体后再次闭合夹爪”可以是正常切换；它不自动成为 `grasp_missed`。一个最终失败的 episode 也可能包含 `nominal` 动作段。`error` 不能仅从最终失败倒推。一个区间若跨越错误、恢复或任务阶段边界，就先拆成多个区间；不能给混合区间贴一个有利标签。

`verified nominal` 表示必需状态可观测、有后续成功或抓取等进展证据支持，且未被当前规则判为错误或待定。当前实现会先用后续进展支持之前的动作，再排除检测到的问题，因此不能解释为逐步确认了动作优质、高效或最优。`verified recovery` 另要求能定位先前的错误及随后纠正的起点。证据要求按任务阶段确定：抓取需要目标物体与夹爪关系，放置需要物体与容器/区域关系，抽屉需要目标关节位置。`coverage=complete` 只指该区间判定所必需的量齐全，不要求收集无关的全部仿真状态。若某个任务没有足够的子目标证据，就保持 `candidate`，不为了提高入选率而把“没发现错误”升级为 `verified`。

### 任务相关的判定规则

**抓取与放置：**从任务目标确定目标物体集合。抓取成立至少要看到目标物体与夹爪形成稳定接触，或已抬升且随末端稳定移动；不能把抬升之后的证据倒推到前面的水平推动。仅有“夹爪闭合”不算抓取。`grasp_missed` 还需要夹爪靠近目标、目标保持静止、末端随后撤离，且这次夹爪动作没有带起别的物体；否则闭合再张开只记为 `gripper_cycle_unresolved`。未确认的夹爪动作之后、下一次确认抓取或目标达成之前，动作保持待判断，不能因后来成功而把重试间隙当作顺利执行。抓错是非目标物体被实际带起；多目标任务中任一尚未完成的目标都算目标。掉落要求物体先被确认携带，后脱离夹爪，且尚未稳定放置到目标位置。放置完成以对应目标条件及稳定后的物体状态为证据，不能只看张开夹爪。

**抽屉等关节任务：**记录目标关节位置及变化方向。移动了非目标抽屉是明确事件；动作幅度小、先调整末端姿态、为避免碰撞而绕行，都不自动判错。

**恢复：**先确认偏差事件，再确定纠正开始与重新取得有效进度的动作。若只有“闭合→张开→闭合”，只能标 `candidate`。错误物体仍被持有、或尚有未确认的夹爪动作时，不能把这段标成已验证恢复。抓错起点标为 error，随后持续持有错误物体的动作标为 uncertain；后续成功不能将它们改为 nominal。再次出错会中断此前的恢复区间，已确认错误与缺证据动作优先于恢复判断。恢复段包含从偏差状态出发且有证据支持的正确动作；导致偏差的动作单独标记。完成多个物体的正常阶段切换不能被误标为恢复。

**慢速、停滞与绕行：**只在同一任务、扰动及相近起点的成功轨迹之间比较任务动作数，不用包含模型等待的墙钟时间。起点难度至少用初始末端到目标距离、目标到放置位置距离和任务物体数作描述；缺少这些量时不强行分难度组。按阶段计算末端路径长度和无目标进展的持续时间；路径短并不等于安全，绕行只作为描述或复核线索。任务需要的静止等待、精细对准及避障不能因为速度低被自动删除。参考轨迹不足时保留原始数值，不生成“快/慢”结论。

### 自动标签文件

每个连续区间一行，保存在 dump 的 `quality-labels.jsonl`；证据值可以指向对应 `oracle-feedback.jsonl` 步数，不复制视频。示意：

```json
{"version":2,"labeler_version":"rules-008","source":"/absolute/episode","source_trace_sha256":"...","oracle_feedback_sha256":"...","task_step_range":[65,83],"task_phase":"approach","role":"uncertain","verification":"candidate","coverage":"complete","events":[{"task_step":70,"event":"gripper_cycle_unresolved","verification":"candidate","evidence":"gripper_command+object_motion+eef_retreat"}],"efficiency":{"eef_path_m":0.12,"stationary_steps":2,"speed_ratio":null,"path_ratio":null,"reference_count":0}}
```

这个示例只说明字段，不是对真实轨迹的判定。区间 `[65,83)` 只包含任务动作 65 至 82。`verification=candidate` 的段不会进入 WLA 训练；`coverage=complete` 也不能把候选事件升级为已确认。`source_trace_sha256` 和 `oracle_feedback_sha256` 绑定两份证据。训练用途不写进事实标签，另由明确版本的选择规则生成训练起点。

`behavior-signals.jsonl` 另存 `slow_relative`、`inefficient_motion`、`repeated_gripper_cycle` 候选区间，含 `source`、`task_step_range`、`kind`、`status=candidate`、`evidence`、`version`。其中慢速只与同任务、同扰动且至少五条参考成功轨迹比较；绕行线索仅在正面动作段计算，跟踪同一目标物体的末端路程、距离回退和净进展，双物体任务不逐帧切换最近物体；重复夹爪周期线索来自未解决夹爪周期或抓空事件，`evidence.cycle_count` 统计这些周期结束事件，不代表有效尝试次数。相邻事件超过 40 步时拆开，但连续事件仍可能串成长段，所以范围仅用于定位证据，不能作为训练片段边界。当前信号版本为 `signals-002`。它们都不能单独证明动作错误。`review-starts.jsonl` 只列这些信号覆盖的、已经实际导出的八步训练起点，供后续查看；当前不自动删除或改变 `nominal/recovery` 标签。

## 不依赖人工标注，提高分类准确性

1. **先扩充并核对仿真真值。**沿用逐步回放和末端位置、官方成功值一致性检查；增加任务相关物体位姿与速度、夹爪接触/相对运动、抽屉关节、目标条件变化。仿真真值只用于离线标注，不输入当时的控制器。真实轨迹缺少这些量时保持 `candidate` 或 `unknown`。
2. **用程序制造已知偏差，再由物理状态验证。**从相同初始状态注入抓取偏移、提前张爪、错误目标、受控碰撞或抽屉目标切换；只有仿真状态确实发生预期事件才收为自动检验样本。另生成正常多物体切换、合理绕行和慢速对准作为难负例。不能把“注入了错误命令”直接当成“错误事件已经发生”。
3. **检验时间一致性。**`target_dropped` 前必须确认曾携带；`recovery` 前必须有偏差；`goal_gained` 要对上目标条件变化。冲突则标 `unknown` 并保存冲突证据。相邻帧短暂接触或目标谓词抖动要用稳定观察窗确认。
4. **比较独立来源。**仿真接触、物体相对运动、目标谓词和双视角图像分别提供证据；SAM 或视觉模型可用于找候选，但不能用同一视觉模型的输出反过来证明自己正确。证据冲突时不自动批准正面示范。
5. **用固定自动检验集衡量标签。**按任务和扰动保留未参与阈值选择的初始状态；检验视觉/运动候选判定时，用独立的仿真接触、关节和目标状态作参照，统计事件精确率、召回率、边界误差及 `unknown` 比例。重点压低 `nominal/recovery` 误收错误动作的比例。若标签本身直接由该仿真真值生成，这项测试只能验证回放与规则实现，不能伪称为独立分类准确率。每次规则或模型更新都重跑固定检验集，并检查自然运行数据中是否出现异常标签分布。

这些措施能检验可观测的物理事件。它们不能凭空证明“某条绕行一定最优”或“某段动作一定提升 WLA”；后者只能用独立训练与评测实验证明。

## 从标签到 WLA 样本

先把“技术上可导出”与“质量上可作为模仿目标”分开。前者要求审计通过、双视频与状态动作对齐、真实未来图存在；后者要求任务相关状态的 `coverage=complete`，且每个获准动作区间的 `role`、`verification` 有物理证据。成功 episode 如果只有最终成功真值，仍属于“质量未判定”，不能叫作已验证的顺畅示范。

第一版把 `verified nominal` 和 `verified recovery` 分成两个正面模仿集合，便于分别 dump；恢复集合只包含偏差之后的正确动作。`candidate` 与 `unknown` 保留原始 trace，并写入未选原因，不自动进入高质量集合。`error` 动作保留作失败检测或以后训练价值模型的资料，不作为当前 WLA 的普通动作目标。最终失败的 episode 也进入逐段分类；其中完成了可验证子目标的正确片段可以产生正面训练起点，不能因为最终失败而把每一步都判坏，也不能因为中途有进展就纳入终点附近的失败动作。速度、绕行与重复动作只存为描述，不直接决定加入或剔除。

WLA 样本从起点 `t` 读取历史前视 `t-8`、当前双视角、状态 `t`、动作 `t:t+8` 和未来前视 `t+8`。一条正面样本须保证监督动作 `t..t+7` 均属于**同一类**获准区间，未来帧 `t+8` 存在且时间对齐。**历史图 `t-8` 可以显示错误后的状态**，它是恢复策略所需的输入，不是错误动作监督。应在原 episode 上保存获准的训练起点，保持真实历史；现有按区间导出为独立 episode 的方式会在区间开头把历史补成首帧，不应作为自动高质量 dump 的最终接口。

建议 LeRobot 数据集保留完整、连续且对齐的 episode（包括最终失败但有可靠正面片段的轨迹），另在数据集自己的 `meta/quality-starts.jsonl` 中逐行保存 `episode_index`、`frame_index`、`set`（`nominal` 或 `recovery`）、标签版本和选择规则版本。例如 `{"episode_index":2,"frame_index":75,"set":"recovery","labeler_version":"rules-001","selection_version":"positive-001"}`。WLA loader 先生成具有真实 `t+8` 图的起点，再与该清单取交集。这样可以从同一份视频导出不同质量集合，且数据集搬运后仍可读取，不依赖原始 trace 路径。清单按 episode/frame 排序去重，保存它所对应的数据集标识与导出版本；同一个起点不能同时属于 `nominal` 和 `recovery`，冲突时需重新切段。loader 遇到不存在、重复、冲突或越界的起点直接报错，不静默退回全量样本。`dump-manifest.json` 记录来源、原始 trace 和 oracle 的哈希、每类起点数；`feedback.jsonl` 按轨迹记录技术拒绝、缺证据、确认错误、可用片段短于八步，以及最终获准起点的数量。完整 trace 与逐段标签另存，供追溯。若暂无质量标签文件，维持现有基础导出模式，但在 manifest 明确标为 `technical_success_only`，不称“高质量”。

质量模式的输入是标签文件及其来源哈希，不是手写的 `review.jsonl`；原有 review 仍可作为额外覆盖决定。标签生成程序、导出器和 loader 必须对同一 `(source, task_step)` 得出一致计数。质量清单缺失、版本不匹配或非空标签却没有可用起点时，质量模式报错，不默默导出全部成功轨迹。

当前 `episode_steps()` 把“动作帧是否对齐”与“整条任务成功”一起检查。之后要提取失败 episode 的正确片段，需把对齐校验拆成独立步骤；由训练起点选择规则决定该片段是否纳入，而不是由原始 episode 的最终成败代替局部质量判断。

当前 WLA `image_action` 训练对动作和未来图像分别计算损失，普通 LeRobot 字段没有“这是错误动作”的负标签语义。把错误动作原样加入训练只会让模型拟合它；若要使用失败作为负面证据，需要另做动作质量条件或价值学习，并独立验证。

## 分类与 dump 的数据飞轮

```text
运行并保存完整轨迹
  → 精确回放、自动事件标签、未知项留存
  → 按规则生成正面动作窗口与恢复窗口，未知窗口单独记账
  → LeRobot 保留完整 episode，质量起点清单决定训练读取哪些窗口
  → 汇总各类事件、未知比例和证据覆盖缺口
  → 在缺口集中的任务阶段定向补采，再重新回放与分类
  → 更新判定器版本，重跑固定自动检验集并重建清单
```

运行时只负责保存原始 episode。episode 完成后，独立的离线任务按来源哈希依次执行回放、分类、选择和导出；同一来源与同一判定器版本重复处理应得到相同结果。分类失败时在反馈里记录失败阶段，原始轨迹仍保留，不能悄悄跳过后把剩余数据称为完整批次。这样自动回流不阻塞 RUA 控制，也不会把仿真真值送进控制器。

这轮先交付标签正确性、清单与数据读取的一致性检查：每个获准起点对应的八个动作均通过选择规则，未来图是真实帧，历史图与原运行一致，计数与反馈一致。训练后效果比较留到下一阶段。飞轮更新时保留原始 trace、规则版本、标签和选择清单；根据证据缺口定向补采，同时保留不同任务、扰动与成功路径的覆盖。没有真实事件证据的自生成标签不能被下一轮模型预测反复“证实”。

## 落地顺序

1. 扩充 `oracle_feedback.py` 的任务相关物理事件，只覆盖当前 pick/place 与 drawer 任务；维持原字段兼容。
2. 新增独立的自动标签产物及程序化偏差检验集，先验证事件和边界，再生成训练选择清单。
3. 将 `episode_steps()` 的动作/视频对齐检查与最终成败判断拆开，导出完整 LeRobot episode 与 `meta/quality-starts.jsonl`；让 WLA loader 按清单读取样本，逐个验证动作窗口、未来图和历史图的时间对齐。
4. 用现有 Pro 轨迹做分类和 dump 的端到端检查，统计各类起点及 `unknown`；训练效果比较作为下一阶段任务。

## 研究依据

- [SCIZOR](https://arxiv.org/abs/2505.22626)：逐状态动作筛选，结合进度估计与去重；其慢速动作简单过滤对照提醒我们不要把速度等同质量。
- [SSDF](https://arxiv.org/abs/2401.08957)：从不完美和失败示范中提取可用片段。
- [RaC](https://arxiv.org/abs/2509.07953)：明确采集偏差后的恢复与纠正动作。
- [PACL](https://arxiv.org/abs/2609.29000)：若要真正利用失败动作的负面信息，训练动作块价值判断，而非将它们无条件混入模仿目标。
